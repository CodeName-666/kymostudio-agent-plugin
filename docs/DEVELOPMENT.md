# Development and release

Python 3.11+ and its standard library are sufficient.

```sh
python -m unittest discover -s tests -v
python tools/package_plugin.py --output dist/release
```

Without `--adapter`, the archives contain only portable plugin files and
instructions. `kymostudio-plugin.zip` contains the plugin root;
`kymostudio-agent-plugin.zip` also contains both marketplaces, README and docs.
Publish these neutral archives. Adapter configurations are generated by the
recipient after installation and are excluded from the public source/release.

Optional native validation:

```sh
claude plugin validate plugins/kymostudio --strict
claude plugin validate .claude-plugin/marketplace.json --strict
```

Codex marketplace installation can be checked with the CLI in an isolated
configuration or a disposable user profile. Native host checks complement the
manifest/path/archive tests. Tests do not run hardware acquisition or contact a
user's existing measurement sessions.

Initial release checks (2026-10-12): 14 standard-library tests passed locally;
Claude Code 2.1.286 accepted both manifests with `--strict` and installed the
marketplace plugin in a disposable configuration directory. Codex CLI 0.162.1
also installed and enabled the plugin with an isolated `CODEX_HOME`.
A generated local stdio configuration was exercised against an isolated packaged
KymoStudio instance: 43 tools discovered, three synthetic signals received,
sample data read and the test source stopped. This proves the adapter connection
and basic workflow; it is not a hardware or acquisition-under-load certification.

For a new version update the portable, Claude and Codex manifests and the Claude
marketplace entry together. Run tests, commit, tag `vX.Y.Z` and create a GitHub
Release with the neutral archives. Incrementing the plugin version is required
for installed clients to receive changed package contents reliably.

This repository tracks the operating contract for KymoStudio MCP. Server and
logging/writer changes belong to the KymoStudio project. Do not copy the desktop
backend or private measurement/configuration files into this repository.

Candidate 0.1.1 adds public-listing metadata, bundled artwork, data handling and
support pages, plus ten submission regression checks (24 tests in total).
0.2.0 follows KymoStudio 2.7: device parameters over the back channel
(`kymo_parameters`, `kymo_parameter_set`, `kymo_parameter_create`,
`kymo_parameter_delete`, `kymo_parameters_request`; a write job succeeds only on a
device confirmation and fails with `DEVICE_REJECTED` or `DEVICE_NO_ANSWER`
otherwise) and opened measurement recordings as `rec<n>-…` signals.
Checked against KymoStudio `integration/2.7` with an ESP32 PI controller.
Run `python tools/check_submission.py` for structural checks. Its success only
means the checked package constraints pass; local application eligibility,
account verification and provider scans remain separate requirements. See
[submission preparation](submission/README.md) for the actual review routes.
